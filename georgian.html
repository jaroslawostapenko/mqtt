სტანდარტი IoT შეტყობინებებისთვის

შეისწავლეთ სრულყოფილად MQTT პროტოკოლი. მსუბუქი, ეფექტური და საიმედო შეტყობინებების სისტემა ნივთების ინტერნეტისთვის (IoT). შექმნილია არასტაბილური ქსელებისა და დაბალი გამტარუნარიანობის გარემოსთვის.

სიმულატორის გაშვება

რა არის MQTT?

MQTT (Message Queuing Telemetry Transport) არის OASIS სტანდარტის შეტყობინებების პროტოკოლი ნივთების ინტერნეტისთვის (IoT). ის შექმნილია როგორც უკიდურესად მსუბუქი publish/subscribe (გამოქვეყნება/გამოწერა) შეტყობინებების ტრანსპორტი, რომელიც იდეალურია დისტანციური მოწყობილობების დასაკავშირებლად მცირე კოდის მოცულობითა და მინიმალური ქსელის გამტარუნარიანობით.

თავდაპირველად შეიქმნა IBM-ის მიერ 1999 წელს სატელიტური კავშირებით ნავთობსადენების მონიტორინგისთვის, ახლა კი იქცა დე-ფაქტო სტანდარტად IoT-სთვის მისი ეფექტურობისა და საიმედოობის გამო არასტაბილურ ქსელებში.

რატომ არის ის ასე პოპულარული?

  • ⚡ მსუბუქი: პაკეტის მინიმალური ზომა მხოლოდ 2 ბაიტია, რაც ამცირებს ქსელის გადატვირთვას.
  • 🛡️ საიმედო: გვთავაზობს მომსახურების ხარისხის (QoS) 3 დონეს მიწოდების უზრუნველსაყოფად.
  • 🔄 ორმხრივი: იძლევა მოწყობილობიდან ღრუბელში და ღრუბლიდან მოწყობილობაში შეტყობინებების გაგზავნის საშუალებას.
  • 💾 მუდმივი: შენახული (Retained) შეტყობინებები ახალ მოწყობილობებს საშუალებას აძლევს დაუყოვნებლივ მიიღონ ბოლო ცნობილი სტატუსი.

შედარება: MQTT vs HTTP

მიუხედავად იმისა, რომ HTTP არის ვებ სტანდარტი, ის მძიმე და დოკუმენტებზე ორიენტირებულია. MQTT ორიენტირებულია მონაცემებზე.

მახასიათებელი MQTT HTTP
დიზაინის მოდელი Pub/Sub მოთხოვნა/პასუხი
ჰედერის ზომა მინ. 2 ბაიტი დიდი (ტექსტური)
კავშირი Keep-Alive გახსნა/დახურვა
ელემენტის მოხმარება ძალიან დაბალი მაღალი
დისტრიბუცია 1-ბევრთან 1-1-თან

არქიტექტურა და კომპონენტები

MQTT პროტოკოლი მიმწოდებელს (გამომცემელს) და მიმღებს (გამომწერს) ერთმანეთისგან აცალკევებს ცენტრალური კომპონენტის საშუალებით, რომელსაც ეწოდება ბროკერი.

ბროკერი

სისტემის გული. ის იღებს ყველა შეტყობინებას, ფილტრავს მათ, წყვეტს ვის აინტერესებს ისინი გამოწერების საფუძველზე და შემდეგ აქვეყნებს შეტყობინებას ყველა გამოწერილ კლიენტთან. პოპულარული ბროკერებია Mosquitto, HiveMQ და EMQX.

გამომცემელი (Publisher)

კლიენტი, რომელიც აგზავნის მონაცემებს (შეტყობინებებს) ბროკერთან კონკრეტულ თემაზე (topic). მაგალითად, ტემპერატურის სენსორი აგზავნის მონაცემებს თემაზე home/livingroom/temp. გამომცემლებს არ სჭირდებათ იცოდნენ ვინ არიან გამომწერები.

გამომწერი (Subscriber)

კლიენტი, რომელიც გამოხატავს ინტერესს კონკრეტული თემის მიმართ. როდესაც ბროკერი იღებს შეტყობინებას ამ თემაზე, ის გადასცემს მას გამომწერს. კლიენტი შეიძლება იყოს ერთდროულად გამომცემელიც და გამომწერიც.

თემების (Topics) გაგება

MQTT თემები არის იერარქიული სტრიქონები, რომლებიც გამოიყენება შეტყობინებების გასაფილტრად. ისინი იყენებენ დახრილ ხაზს / როგორც გამყოფს. ისინი მგრძნობიარეა რეგისტრის მიმართ (case-sensitive).

თემის სტრუქტურა

ტიპური თემა ასე გამოიყურება:

myhome / groundfloor / kitchen / temp

ეს იერარქია მოწყობილობების სპეციფიკური მისამართების მინიჭების საშუალებას იძლევა.

თემის Wildcard-ები

  • ერთ დონიანი (+):
    home/+/temp ემთხვევა home/kitchen/temp, მაგრამ არა home/kitchen/fridge/temp.
  • მრავალ დონიანი (#):
    home/# ემთხვევა ყველაფერს, რაც იწყება home-ით, მაგ., home/kitchen/temp და home/garage/light/status. ეს უნდა იყოს ბოლო სიმბოლო თემაში.

ვებ MQTT სიმულატორი

გამოსცადეთ როგორ მუშაობს MQTT პირდაპირ თქვენს ბრაუზერში. ეს სიმულატორი ადგილობრივად ბაძავს ბროკერისა და კლიენტის ქცევას JavaScript ლოგიკის გამოყენებით.

მომსახურების ხარისხი (QoS)

MQTT გთავაზობთ შეტყობინებების მიწოდების სამ კონკრეტულ ხარისხს. ეს საშუალებას აძლევს დეველოპერს აირჩიოს სწორი ბალანსი დანახარჯებსა და საიმედოობას შორის კონკრეტული შეტყობინებებისთვის.

მაქსიმუმ ერთხელ

ასევე ცნობილია როგორც "გაისროლე და დაივიწყე" (Fire and forget). შეტყობინება იგზავნება ერთხელ. დადასტურება არ არის მოსალოდნელი. თუ კავშირი გაწყდება ან სერვერი დაკავებულია, შეტყობინება სამუდამოდ დაიკარგება.

გამოყენების შემთხვევა: ტემპერატურის სენსორის პერიოდული მონაცემები, სადაც ასიდან ერთი მონაცემის გამოტოვება არ არის კრიტიკული.

QoS 1

მინიმუმ ერთხელ

იძლევა გარანტიას, რომ შეტყობინება მიწოდებული იქნება მინიმუმ ერთხელ მიმღებამდე. გამომგზავნი ინახავს შეტყობინებას მანამ, სანამ არ მიიღებს PUBACK პაკეტს. დუბლიკატები შეიძლება მოხდეს, თუ დადასტურება დაიკარგება.

გამოყენების შემთხვევა: სინათლის ჩამრთველის ჩართვა. თქვენ ნამდვილად გსურთ რომ ის ჩაირთოს და ამის ორჯერ გაკეთება მისაღებია.

ზუსტად ერთხელ

ყველაზე უსაფრთხო და ნელი დონე. იძლევა გარანტიას, რომ შეტყობინება მიიღება ზუსტად ერთხელ ოთხ-საფეხურიანი დადასტურების გამოყენებით. ეს თავიდან აიცილებს დუბლიკატებს.

გამოყენების შემთხვევა: საბანკო ტრანზაქციები, ბილინგის სისტემები ან კრიტიკული სიგნალიზაციები, სადაც დუბლიკატები იწვევს შეცდომებს.

იმპლემენტაციის მაგალითები

MQTT-ს აქვს კლიენტის ბიბლიოთეკები ხელმისაწვდომი თითქმის ყველა პროგრამირების ენისთვის (C, C++, Java, Python, Go, JavaScript და ა.შ.).

Python (Paho-MQTT)

სტანდარტული ბიბლიოთეკა Python IoT აპლიკაციებისთვის.

import paho.mqtt.client as mqtt

# Callback ფუნქცია დაკავშირებისას
def on_connect(client, userdata, flags, rc):
    print(f"Connected with result code {rc}")
    # on_connect-ში გამოწერა უზრუნველყოფს 
    # ხელახალ გამოწერას კავშირის გაწყვეტის შემთხვევაში
    client.subscribe("home/sensors/#")

# Callback ფუნქცია შეტყობინების მიღებისას
def on_message(client, userdata, msg):
    print(f"{msg.topic}: {msg.payload.decode()}")

client = mqtt.Client()
client.on_connect = on_connect
client.on_message = on_message

client.connect("broker.hivemq.com", 1883, 60)
client.loop_forever()

JavaScript (Node.js)

MQTT.js ბიბლიოთეკის გამოყენება ასინქრონული ოპერაციებისთვის.

const mqtt = require('mqtt')
// საჯარო ტესტ-ბროკერთან დაკავშირება
const client  = mqtt.connect('mqtt://test.mosquitto.org')

client.on('connect', function () {
  console.log("Connected!")
  
  // presence თემის გამოწერა
  client.subscribe('presence', function (err) {
    if (!err) {
      // შეტყობინების გამოქვეყნება
      client.publish('presence', 'Hello mqtt')
    }
  })
})

client.on('message', function (topic, message) {
  // შეტყობინება არის Buffer
  console.log(message.toString())
  client.end() // კავშირის დახურვა
})

ხშირად დასმული კითხვები

ნაგულისხმევად, MQTT მონაცემებს აგზავნის ღია ტექსტის სახით, რაც არ არის უსაფრთხო. თუმცა, პროდუქციული იმპლემენტაციები, როგორც წესი, იყენებენ TLS/SSL-ს კავშირის დასაშიფრად (MQTTS), ძირითადად პორტზე 8883. გარდა ამისა, მომხმარებლის/პაროლის ავთენტიფიკაცია და კლიენტის სერთიფიკატები შეიძლება გამოყენებულ იქნას მოწყობილობების ავტორიზაციისთვის ბროკერის დონეზე.

შენახული შეტყობინება არის ჩვეულებრივი MQTT შეტყობინება "retained" დროშით (flag), რომელიც მონიშნულია როგორც true. ბროკერი ინახავს ბოლო შენახულ შეტყობინებას ამ თემისთვის. როდესაც ახალი კლიენტი იწერს ამ თემას, ის დაუყოვნებლივ იღებს შენახულ შეტყობინებას. ეს სასარგებლოა "სტატუსის" განახლებებისთვის (მაგ. ბოლო ცნობილი ტემპერატურის მიწოდება მოწყობილობისთვის, რომელიც ახლახან ჩაირთო).

LWT არის ფუნქცია, სადაც კლიენტი უთითებს შეტყობინებას, რომელიც ავტომატურად უნდა გამოქვეყნდეს ბროკერის მიერ, თუ კლიენტი არასწორად გაითიშება (მაგ., ელემენტი დაჯდება, ქსელის შეფერხება). ეს სხვა კლიენტებს საშუალებას აძლევს იცოდნენ, რომ მოწყობილობა მოულოდნელად გამოირთო.

სტანდარტული MQTT იყენებს TCP პორტს 1883. MQTT SSL/TLS-ით იყენებს პორტს 8883. MQTT WebSocket-ებით ჩვეულებრივ იყენებს პორტს 80 ან 443 (თუ დაცულია), ან მორგებულ პორტებს, როგორიცაა 9001, ბროკერის კონფიგურაციიდან გამომდინარე.

როდესაც კლიენტი უკავშირდება პარამეტრით "Clean Session = false", ბროკერი ქმნის მუდმივ სესიას. ის ინახავს ყველა გამოწერას და რიგში აყენებს QoS 1 და 2 შეტყობინებებს კლიენტისთვის, სანამ ის ხაზგარეშეა. როდესაც კლიენტი ხელახლა დაკავშირდება, ის იღებს ყველა გამოტოვებულ შეტყობინებას.

MQTT-ის შესახებ

ჩვენ გთავაზობთ ყველაზე სრულყოფილ დოკუმენტაციას და ინსტრუმენტებს დეველოპერებისთვის, რომლებიც ქმნიან IoT გადაწყვეტილებებს MQTT პროტოკოლის გამოყენებით. ჩვენი მისიაა IoT კავშირი ყველასთვის ხელმისაწვდომი გავხადოთ.
