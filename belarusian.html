Стандарт для абмену паведамленнямі ў IoT

Асвойце пратакол MQTT. Лёгкая, эфектыўная і надзейная сістэма абмену паведамленнямі для Інтэрнэту рэчаў. Створана для нестабільных сетак і ўмоў з нізкай прапускной здольнасцю.

Запусціць сімулятар

Што такое MQTT?

MQTT (Message Queuing Telemetry Transport) — гэта стандартны пратакол абмену паведамленнямі (OASIS) для Інтэрнэту рэчаў (IoT). Ён распрацаваны як надзвычай лёгкі транспарт для абмену паведамленнямі па мадэлі "публікацыя/падпіска" (publish/subscribe), які ідэальна падыходзіць для падключэння аддаленых прылад з невялікім аб'ёмам кода і мінімальнай прапускной здольнасцю сеткі.

Першапачаткова распрацаваны IBM у 1999 годзе для маніторынгу нафтаправодаў праз спадарожнікавую сувязь, цяпер ён стаў дэ-факта стандартам для IoT дзякуючы сваёй эфектыўнасці і надзейнасці ў нестабільных сетках.

Чаму ён такі папулярны?

  • ⚡ Лёгкі: Мінімальны памер пакета складае ўсяго 2 байты, што зніжае нагрузку на сетку.
  • 🛡️ Надзейны: Прапануе 3 ўзроўні якасці абслугоўвання (QoS) для гарантыі дастаўкі.
  • 🔄 Двухбаковы: Дазваляе абменьвацца паведамленнямі паміж прыладай і воблакам (device-to-cloud) і наадварот.
  • 💾 Захаванне стану: Захаваныя паведамленні (Retained messages) дазваляюць новым прыладам неадкладна атрымліваць апошні вядомы стан.

Параўнанне: MQTT супраць HTTP

У той час як HTTP з'яўляецца вэб-стандартам, ён цяжкі і арыентаваны на дакументы. MQTT арыентаваны на дадзеныя.

Архітэктура і кампаненты

Пратакол MQTT падзяляе адпраўніка (выдаўца) і атрымальніка (падпісчыка) праз цэнтральны кампанент, які называецца Брокерам.

Брокер (Broker)

Сэрца сістэмы. Ён атрымлівае ўсе паведамленні, фільтруе іх, вырашае, каму яны цікавыя на аснове падпісак, а затым публікуе паведамленне ўсім падпісаным кліентам. Папулярныя брокеры: Mosquitto, HiveMQ і EMQX.

Выдавец (Publisher)

Кліент, які адпраўляе дадзеныя (паведамленні) брокеру на пэўную тэму (topic). Напрыклад, датчык тэмпературы публікуе дадзеныя ў home/livingroom/temp. Выдаўцам не трэба ведаць, хто з'яўляецца падпісчыкам.

Падпісчык (Subscriber)

Кліент, які рэгіструе цікавасць да пэўнай тэмы. Калі брокер атрымлівае паведамленне на гэтую тэму, ён перасылае яго падпісчыку. Кліент можа быць адначасова і выдаўцом, і падпісчыкам.

Разуменне тэм (Topics)

Тэмы MQTT — гэта іерархічныя радкі, якія выкарыстоўваюцца для фільтрацыі паведамленняў. Яны выкарыстоўваюць прамую касую рысу / у якасці раздзяляльніка. Яны адчувальныя да рэгістра.

Структура тэмы

Тыповая тэма выглядае так:

myhome / groundfloor / kitchen / temp

Гэтая іерархія дазваляе спецыфічна адрасаваць прылады.

Сімвалы падстаноўкі (Wildcards)

  • Адзін узровень (+):
    home/+/temp супадае з home/kitchen/temp, але не з home/kitchen/fridge/temp.
  • Шмат узроўняў (#):
    home/# супадае з усім, што пачынаецца з home, напрыклад, home/kitchen/temp і home/garage/light/status. Гэта павінен быць апошні сімвал у тэме.

Якасць абслугоўвання (QoS)

MQTT забяспечвае тры пэўныя ўзроўні якасці абслугоўвання для дастаўкі паведамленняў. Гэта дазваляе распрацоўшчыку выбраць правільны баланс паміж выдаткамі і надзейнасцю для пэўных паведамленняў.

0

QoS 0

Не больш за адзін раз

Таксама вядомы як "Выстраліў і забыўся" (Fire and forget). Паведамленне адпраўляецца адзін раз. Пацвярджэнне не чакаецца. Калі злучэнне перапыняецца або сервер заняты, паведамленне губляецца назаўжды.

Выпадак выкарыстання: Перыядычныя дадзеныя датчыка тэмпературы, дзе пропуск аднаго паказання са ста не з'яўляецца крытычным.

1

QoS 1

Хаця б адзін раз

Гарантуе, што паведамленне будзе дастаўлена атрымальніку хаця б адзін раз. Адпраўнік захоўвае паведамленне, пакуль не атрымае пакет PUBACK. Дублікаты могуць узнікнуць, калі пацвярджэнне згубіцца.

Выпадак выкарыстання: Уключэнне выключальніка святла. Вы дакладна хочаце, каб ён уключыўся, і зрабіць гэта двойчы - прымальна.

2

QoS 2

Дакладна адзін раз

Самы бяспечны і павольны ўзровень. Гарантуе, што паведамленне будзе атрымана дакладна адзін раз з дапамогай чатырохэтапнага ўзгаднення (handshake). Гэта прадухіляе дубліраванне.

Выпадак выкарыстання: Банкаўскія транзакцыі, білінгавыя сістэмы або крытычныя сігналы трывогі, дзе дублікаты выклікаюць памылкі.

Прыклады рэалізацыі

Для MQTT даступныя кліенцкія бібліятэкі амаль для кожнай мовы праграмавання (C, C++, Java, Python, Go, JavaScript і г.д.).

Python (Paho-MQTT)

Стандартная бібліятэка для праграм Python IoT.

import paho.mqtt.client as mqtt

# Callback пры падключэнні
def on_connect(client, userdata, flags, rc):
    print(f"Connected with result code {rc}")
    # Падпіска ў on_connect гарантуе паўторную падпіску 
    # пры страце злучэння
    client.subscribe("home/sensors/#")

# Callback пры атрыманні паведамлення
def on_message(client, userdata, msg):
    print(f"{msg.topic}: {msg.payload.decode()}")

client = mqtt.Client()
client.on_connect = on_connect
client.on_message = on_message

client.connect("broker.hivemq.com", 1883, 60)
client.loop_forever()

JavaScript (Node.js)

Выкарыстанне бібліятэкі MQTT.js для асінхронных аперацый.

const mqtt = require('mqtt')
// Падключэнне да публічнага тэставага брокера
const client  = mqtt.connect('mqtt://test.mosquitto.org')

client.on('connect', function () {
  console.log("Connected!")
  
  // Падпіска на тэму presence
  client.subscribe('presence', function (err) {
    if (!err) {
      // Апублікаваць паведамленне
      client.publish('presence', 'Hello mqtt')
    }
  })
})

client.on('message', function (topic, message) {
  // message - гэта Buffer
  console.log(message.toString())
  client.end() // Закрыць злучэнне
})

Часта задаваныя пытанні

Па змаўчанні MQTT адпраўляе дадзеныя ў адкрытым тэксце, што не з'яўляецца бяспечным. Аднак вытворчыя рэалізацыі звычайна выкарыстоўваюць TLS/SSL для шыфравання злучэння (MQTTS), звычайна на порце 8883. Акрамя таго, для аўтарызацыі прылад на ўзроўні брокера можна выкарыстоўваць аўтэнтыфікацыю па імені карыстальніка/паролі і кліенцкія сертыфікаты.

Захаванае паведамленне - гэта звычайнае паведамленне MQTT з устаноўленым у true сцягам "retained". Брокер захоўвае апошняе захаванае паведамленне для гэтай тэмы. Калі новы кліент падпісваецца на гэтую тэму, ён неадкладна атрымлівае захаванае паведамленне. Гэта карысна для "абнаўленняў статусу" (напрыклад, прадастаўлення апошняй вядомай тэмпературы прыладзе, якая толькі што прачнулася).

LWT (Last Will and Testament) - гэта функцыя, пры якой кліент пазначае паведамленне, якое аўтаматычна публікуецца брокерам, калі кліент нечакана адключаецца (напрыклад, садзіцца батарэя, збой сеткі). Гэта дазваляе іншым кліентам ведаць, што прылада нечакана перайшла ў аўтаномны рэжым.

Стандартны MQTT выкарыстоўвае порт TCP 1883. MQTT праз SSL/TLS выкарыстоўвае порт 8883. MQTT праз WebSockets звычайна выкарыстоўвае порт 80 або 443 (калі абаронены), або карыстальніцкія парты, такія як 9001, у залежнасці ад канфігурацыі брокера.

Калі кліент падключаецца з параметрамі "Clean Session = false", брокер стварае пастаянную сесію. Ён захоўвае ўсе падпіскі і ставіць у чаргу паведамленні QoS 1 і 2 для кліента, пакуль ён знаходзіцца ў аўтаномным рэжыме. Калі кліент падключаецца зноў, ён атрымлівае ўсе прапушчаныя паведамленні.
