Az IoT Üzenetküldés Szabványa

Sajátítsa el az MQTT protokollt. Könnyűsúlyú, hatékony és megbízható üzenetküldés a Dolgok Internete számára. Kifejezetten instabil hálózatokhoz és alacsony sávszélességű környezetekhez tervezve.

Szimulátor Indítása

Mi az az MQTT?

Az MQTT (Message Queuing Telemetry Transport) egy OASIS szabványú üzenetküldési protokoll a Dolgok Internete (IoT) számára. Rendkívül könnyűsúlyú, közzétevő/feliratkozó (publish/subscribe) alapú üzenetküldési megoldásként tervezték, amely ideális kis kódméretű és minimális hálózati sávszélességgel rendelkező távoli eszközök csatlakoztatására.

Eredetileg az IBM fejlesztette ki 1999-ben olajvezetékek műholdas kapcsolatokon keresztül történő megfigyelésére, mára azonban az instabil hálózatokon mutatott hatékonysága és megbízhatósága miatt az IoT de-facto szabványává vált.

Miért olyan népszerű?

  • ⚡ Könnyűsúlyú: A legkisebb csomagméret mindössze 2 bájt, ami csökkenti a hálózati terhelést.
  • 🛡️ Megbízható: 3 szintű Szolgáltatás Minőséget (QoS) kínál a kézbesítés garantálására.
  • 🔄 Kétirányú: Lehetővé teszi az üzenetküldést az eszköztől a felhőig és a felhőtől az eszközig.
  • 💾 Perzisztens (Megtartott): A megtartott üzenetek (retained messages) lehetővé teszik, hogy az új eszközök azonnal megkapják az utolsó ismert állapotot.

Architektúra és Komponensek

Az MQTT protokoll elválasztja a küldőt (közzétevő) és a fogadót (feliratkozó) egy központi komponens, a Bróker (Broker) segítségével.

A Bróker

A rendszer szíve. Fogadja az összes üzenetet, szűri őket, a feliratkozások alapján eldönti, kit érdekelnek, majd továbbítja (közzéteszi) az üzenetet az összes feliratkozott kliensnek. Népszerű brókerek például a Mosquitto, a HiveMQ és az EMQX.

Közzétevő (Publisher)

Olyan kliens, amely adatokat (üzeneteket) küld a brókernek egy adott témakörben (topic). Például egy hőmérséklet-érzékelő, amely adatokat tesz közzé a haz/nappali/homerseklet témakörben. A közzétevőknek nem kell tudniuk, kik a feliratkozók.

Feliratkozó (Subscriber)

Olyan kliens, amely jelzi érdeklődését egy adott témakör iránt. Amikor a bróker üzenetet kap ebben a témakörben, továbbítja azt a feliratkozónak. Egy kliens egyszerre lehet közzétevő és feliratkozó is.

Témakörök (Topics) Megértése

Az MQTT témakörök hierarchikus karakterláncok, amelyeket az üzenetek szűrésére használnak. Elválasztóként perjelet / használnak. A kis- és nagybetűk megkülönböztetése (case-sensitive) számít.

Témakör felépítése

Egy tipikus témakör így néz ki:

hazam / foldszint / konyha / homerseklet

Ez a hierarchia lehetővé teszi az eszközök specifikus címzését.

Helyettesítő karakterek (Wildcards)

  • Egyszintű (+):
    A haz/+/homerseklet illeszkedik a haz/konyha/homerseklet témakörre, de a haz/konyha/huto/homerseklet témakörre nem.
  • Többszintű (#):
    A haz/# mindenre illeszkedik, ami a haz szóval kezdődik, pl. haz/konyha/homerseklet és haz/garazs/lampa/allapot. Ennek a karakternek kell az utolsónak lennie a témakörben.

Szolgáltatás Minősége (QoS)

Az MQTT három specifikus szolgáltatási minőségi (QoS) szintet biztosít az üzenetküldéshez. Ez lehetővé teszi a tervező számára, hogy az adott üzenetek esetében megtalálja a megfelelő egyensúlyt a hálózati többletterhelés és a megbízhatóság között.

0

QoS 0

Legfeljebb egyszer

Más néven "Tüzelj és felejtsd el" (Fire and forget). Az üzenetet csak egyszer küldi el. Nincs szükség visszaigazolásra. Ha a kapcsolat megszakad vagy a szerver foglalt, az üzenet örökre elvész.

Felhasználási eset: Időszakos hőmérséklet-érzékelő adatok, ahol százból egy mérés hiánya nem kritikus.

1

QoS 1

Legalább egyszer

Garantálja, hogy egy üzenet legalább egyszer kézbesítésre kerül a fogadónak. A küldő addig tárolja az üzenetet, amíg egy PUBACK csomagot nem kap. Előfordulhatnak duplikátumok, ha a visszaigazolás elvész.

Felhasználási eset: Villanykapcsoló felkapcsolása. Mindenképpen szeretné, ha felkapcsolódna, és az sem baj, ha a parancs kétszer fut le.

2

QoS 2

Pontosan egyszer

A legbiztonságosabb és leglassabb szint. Négy lépésből álló kézfogás (handshake) segítségével garantálja, hogy az üzenet pontosan egyszer érkezzen meg. Ez megakadályozza a duplikációkat.

Felhasználási eset: Banki tranzakciók, számlázási rendszerek vagy kritikus riasztások, ahol a duplikátumok hibákat okoznának.

Implementációs Példák

Az MQTT szinte minden programozási nyelvhez (C, C++, Java, Python, Go, JavaScript stb.) rendelkezik klienskönyvtárral.

Python (Paho-MQTT)

A szabványos könyvtár Python IoT alkalmazásokhoz.

import paho.mqtt.client as mqtt

# Visszahívás (callback), ha csatlakozott
def on_connect(client, userdata, flags, rc):
    print(f"Csatlakozva, eredmenykod: {rc}")
    # A feliratkozás az on_connect-ben biztosítja, 
    # hogy újracsatlakozáskor újra feliratkozzunk
    client.subscribe("haz/szenzorok/#")

# Visszahívás (callback) üzenet érkezésekor
def on_message(client, userdata, msg):
    print(f"{msg.topic}: {msg.payload.decode()}")

client = mqtt.Client()
client.on_connect = on_connect
client.on_message = on_message

client.connect("broker.hivemq.com", 1883, 60)
client.loop_forever()

JavaScript (Node.js)

Az MQTT.js könyvtár használata aszinkron műveletekhez.

const mqtt = require('mqtt')
// Csatlakozás egy nyilvános teszt brókerhez
const client  = mqtt.connect('mqtt://test.mosquitto.org')

client.on('connect', function () {
  console.log("Csatlakozva!")
  
  // Feliratkozás a jelenlét (presence) témakörre
  client.subscribe('jelenlet', function (err) {
    if (!err) {
      // Üzenet közzététele
      client.publish('jelenlet', 'Helló mqtt')
    }
  })
})

client.on('message', function (topic, message) {
  // A message egy Buffer objektum
  console.log(message.toString())
  client.end() // Kapcsolat lezárása
})

Gyakran Ismételt Kérdések (GYIK)

Alapértelmezés szerint az MQTT egyszerű szövegként (plain text) küldi az adatokat, ami nem biztonságos. A termelési (éles) implementációk azonban jellemzően TLS/SSL-t használnak a kapcsolat titkosítására (MQTTS), általában a 8883-as porton. Ezenkívül a bróker szintjén felhasználónév/jelszó hitelesítéssel és Kliens Tanúsítványokkal (Client Certificates) is engedélyezhetők az eszközök.

A megtartott üzenet egy normál MQTT üzenet, amelynél a "retained" jelző true (igaz) értékre van állítva. A bróker elmenti az adott témakör utolsó megtartott üzenetét. Amikor egy új kliens feliratkozik erre a témakörre, azonnal megkapja ezt a megtartott üzenetet. Ez nagyon hasznos "állapot" (status) frissítésekhez (pl. a legutóbbi ismert hőmérséklet elküldése egy éppen felébredt eszköznek).

Az LWT egy olyan funkció, amelyben a kliens előre meghatároz egy üzenetet, amelyet a bróker automatikusan közzétesz, ha a kliens kapcsolata váratlanul megszakad (pl. lemerül az akkumulátor, hálózati hiba történik). Ez lehetővé teszi a többi kliens számára, hogy értesüljenek arról, ha egy eszköz váratlanul offline állapotba került.

A szabványos MQTT a TCP 1883-as portot használja. Az SSL/TLS feletti MQTT (MQTTS) a 8883-as portot használja. A WebSocketeken keresztüli MQTT általában a 80-as vagy 443-as portot (ha biztonságos) használja, illetve egyedi portokat, például a 9001-et, a bróker konfigurációjától függően.

Amikor egy kliens "Clean Session = false" beállítással csatlakozik, a bróker egy állandó (perzisztens) munkamenetet hoz létre. Elmenti az összes feliratkozást, és amíg a kliens offline van, sorba állítja számára a QoS 1 és 2 üzeneteket. Amikor a kliens újra csatlakozik, megkapja az összes kihagyott üzenetet.
