IoT ziņojumapmaiņas standarts

Apgūstiet MQTT protokolu. Viegla, efektīva un uzticama ziņojumapmaiņa Lietu internetam (IoT). Izstrādāta nestabiliem tīkliem un zema joslas platuma vidēm.

Palaist simulatoru

Kas ir MQTT?

MQTT (Message Queuing Telemetry Transport) ir OASIS standarta ziņojumapmaiņas protokols Lietu internetam (IoT). Tas ir izstrādāts kā īpaši viegls publikācijas/abonēšanas (publish/subscribe) ziņojumapmaiņas transports, kas ir ideāli piemērots attālinātu ierīču savienošanai ar mazu koda apjomu un minimālu tīkla joslas platumu.

Sākotnēji to 1999. gadā izstrādāja IBM, lai uzraudzītu naftas vadus, izmantojot satelītsavienojumus. Mūsdienās tas ir kļuvis par "de-facto" standartu IoT ierīcēm, pateicoties tā efektivitātei un uzticamībai nestabilos tīklos.

Kāpēc tas ir tik populārs?

  • ⚡ Viegls: Mazākais paketes izmērs ir tikai 2 baiti, kas samazina tīkla noslodzi.
  • 🛡️ Uzticams: Piedāvā 3 pakalpojuma kvalitātes (QoS) līmeņus, lai garantētu piegādi.
  • 🔄 Divvirzienu: Ļauj nosūtīt ziņojumus gan no ierīces uz mākoni, gan no mākoņa uz ierīci.
  • 💾 Pastāvīgs: Aizturētie (retained) ziņojumi ļauj jaunām ierīcēm uzreiz saņemt pēdējo zināmo stāvokli.

Salīdzinājums: MQTT pret HTTP

Lai gan HTTP ir tīmekļa standarts, tas ir "smags" un orientēts uz dokumentiem. MQTT ir orientēts uz datiem.

Arhitektūra un komponenti

MQTT protokols nošķir sūtītāju (izdevēju) un saņēmēju (abonentu) ar centrālā komponenta palīdzību, ko sauc par Brokeri.

Brokeris

Sistēmas sirds. Tas saņem visus ziņojumus, filtrē tos, izlemj, kurus tie interesē, balstoties uz abonementiem, un pēc tam publicē ziņojumu visiem abonētajiem klientiem. Populāri brokeri ir Mosquitto, HiveMQ un EMQX.

Izdevējs (Publisher)

Klients, kas sūta datus (ziņojumus) brokerim par noteiktu tēmu (topic). Piemēram, temperatūras sensors, kas publicē datus uz māja/dzīvojamā_istaba/temp. Izdevējiem nav jāzina, kas ir abonenti.

Abonents (Subscriber)

Klients, kas reģistrē interesi par konkrētu tēmu. Kad brokeris saņem ziņojumu par šo tēmu, tas pārsūta to abonentam. Klients vienlaikus var būt gan izdevējs, gan abonents.

Tēmu (Topics) izpratne

MQTT tēmas ir hierarhiskas virknes, ko izmanto ziņojumu filtrēšanai. Tās izmanto slīpsvītru / kā atdalītāju. Tēmas ir reģistrjutīgas (atšķir lielos un mazos burtus).

Tēmas struktūra

Tipiska tēma izskatās šādi:

manamaja / pirmais_stavs / virtuve / temp

Šī hierarhija ļauj precīzi adresēt ierīces.

Aizstājējzīmes (Wildcards)

  • Viens līmenis (+):
    māja/+/temp atbilst māja/virtuve/temp, bet ne māja/virtuve/ledusskapis/temp.
  • Vairāki līmeņi (#):
    māja/# atbilst visam, kas sākas ar "māja", piemēram, māja/virtuve/temp un māja/garāža/gaisma/statuss. Šai zīmei jābūt pēdējai tēmas nosaukumā.

Pakalpojuma kvalitāte (QoS)

MQTT nodrošina trīs specifiskus pakalpojumu kvalitātes līmeņus ziņojumu piegādei. Tas ļauj izstrādātājam izvēlēties pareizo līdzsvaru starp tīkla noslodzi un uzticamību konkrētiem ziņojumiem.

0

QoS 0

Ne vairāk kā vienu reizi

Pazīstams arī kā "Izšauj un aizmirsti" (Fire and forget). Ziņojums tiek nosūtīts vienu reizi. Apstiprinājums netiek gaidīts. Ja savienojums pārtrūkst vai serveris ir aizņemts, ziņojums tiek neatgriezeniski zaudēts.

Izmantošanas gadījums: Periodiski temperatūras sensora dati, kur viena rādījuma izlaišana no simta nav kritiska.

1

QoS 1

Vismaz vienu reizi

Garantē, ka ziņojums saņēmējam tiks piegādāts vismaz vienu reizi. Sūtītājs saglabā ziņojumu, līdz saņem PUBACK paketi. Ja apstiprinājums (ack) tiek zaudēts, var rasties dublikāti.

Izmantošanas gadījums: Gaismas slēdža ieslēgšana. Jūs noteikti vēlaties, lai tas ieslēgtos, un tas, ka tas tiks izdarīts divreiz, ir pieņemami.

2

QoS 2

Tieši vienu reizi

Drošākais un lēnākais līmenis. Garantē, ka ziņojums tiek saņemts tieši vienu reizi, izmantojot četru pakāpju saziņas ("handshake") procesu. Tas novērš dublikātus.

Izmantošanas gadījums: Bankas darījumi, norēķinu sistēmas vai kritiskas trauksmes, kur dublikāti rada kļūdas.

Implementācijas piemēri

MQTT klientu bibliotēkas ir pieejamas gandrīz katrai programmēšanas valodai (C, C++, Java, Python, Go, JavaScript utt.).

Python (Paho-MQTT)

Standarta bibliotēka Python IoT lietojumprogrammām.

import paho.mqtt.client as mqtt

# Atsaukums (Callback), kad pievienots
def on_connect(client, userdata, flags, rc):
    print(f"Pievienots ar rezultāta kodu {rc}")
    # Abonēšana iekš on_connect nodrošina, ka 
    # atjaunosim abonementu, ja zaudēsim savienojumu
    client.subscribe("māja/sensori/#")

# Atsaukums, kad saņemts ziņojums
def on_message(client, userdata, msg):
    print(f"{msg.topic}: {msg.payload.decode()}")

client = mqtt.Client()
client.on_connect = on_connect
client.on_message = on_message

client.connect("broker.hivemq.com", 1883, 60)
client.loop_forever()

JavaScript (Node.js)

Izmantojot MQTT.js bibliotēku asinhronām operācijām.

const mqtt = require('mqtt')
// Pievienoties publiskam testa brokerim
const client  = mqtt.connect('mqtt://test.mosquitto.org')

client.on('connect', function () {
  console.log("Pievienots!")
  
  // Abonēt klātbūtnes (presence) tēmu
  client.subscribe('klatbutne', function (err) {
    if (!err) {
      // Publicēt ziņojumu
      client.publish('klatbutne', 'Sveiks, mqtt')
    }
  })
})

client.on('message', function (topic, message) {
  // message ir Buffer (buferis)
  console.log(message.toString())
  client.end() // Aizvērt savienojumu
})

Bieži uzdotie jautājumi (BUJ)

Pēc noklusējuma MQTT sūta datus kā vienkāršu tekstu, kas nav droši. Taču ražošanas (production) vidē parasti tiek izmantots TLS/SSL, lai šifrētu savienojumu (MQTTS), visbiežāk izmantojot portu 8883. Papildus brokeru līmenī var izmantot lietotājvārda/paroles autentifikāciju un Klientu sertifikātus ierīču autorizācijai.

Aizturētais ziņojums ir parasts MQTT ziņojums ar "retained" karogu, kas iestatīts uz "true". Brokeris saglabā pēdējo aizturēto ziņojumu attiecīgajai tēmai. Kad jauns klients abonē šo tēmu, tas uzreiz saņem šo aizturēto ziņojumu. Tas ir noderīgi "statusa" atjauninājumiem (piem., nodrošinot pēdējo zināmo temperatūru ierīcei, kura tikko pamodās).

LWT ir funkcija, kurā klients norāda ziņojumu, ko brokeris automātiski publicēs, ja klients negaidīti atvienosies (piem., izlādējas akumulators, tīkla kļūme). Tas ļauj citiem klientiem uzzināt, ka ierīce negaidīti ir kļuvusi bezsaistē.

Standarta MQTT izmanto TCP portu 1883. MQTT caur SSL/TLS izmanto portu 8883. MQTT caur WebSockets parasti izmanto portu 80 vai 443 (ja ir drošs savienojums), vai pielāgotus portus, piemēram, 9001, atkarībā no brokera konfigurācijas.

Kad klients pievienojas ar iestatījumu "Clean Session = false", brokeris izveido pastāvīgu sesiju. Tas saglabā visus abonementus un izveido rindu ar QoS 1 un 2 ziņojumiem klientam, kamēr tas ir bezsaistē. Kad klients atkal pieslēdzas, tas saņem visus nokavētos ziņojumus.
