什么是 MQTT？

MQTT（消息队列遥测传输）是物联网 (IoT) 的 OASIS 标准消息传递协议。它被设计为一种极其轻量级的发布/订阅 (Publish/Subscribe) 消息传输机制，非常适合用于连接代码占用量小且网络带宽极小的远程设备。

它最初由 IBM 在 1999 年开发，用于通过卫星连接监控石油管道，由于其在不稳定网络上的高效性和可靠性，如今已成为物联网的通用标准。

为什么它如此受欢迎？

  • ⚡ 轻量级： 最小的包大小仅为 2 个字节，极大地减少了网络开销。
  • 🛡️ 可靠： 提供 3 个级别的服务质量 (QoS) 以确保消息的成功送达。
  • 🔄 双向通信： 允许设备到云端以及云端到设备之间的消息传递。
  • 💾 持久性： 保留消息 (Retained messages) 允许新接入的设备立即获取最后已知的状态。

比较：MQTT 与 HTTP

虽然 HTTP 是 Web 标准，但它非常沉重并且以文档为中心。而 MQTT 是以数据为中心的。

特性 MQTT HTTP
设计模式 发布/订阅 (Pub/Sub) 请求/响应
请求头大小 最小 2 字节 大（基于文本）
连接方式 保持活动 (Keep-Alive) 打开/关闭
电池消耗 非常低 高
分发方式 一对多 一对一

架构与组件

MQTT 协议通过称为代理 (Broker) 的中央组件，解除了发送者（发布者）和接收者（订阅者）之间的直接耦合。

代理 (Broker)

系统的核心。它接收所有的消息，过滤它们，根据订阅情况决定谁对这些消息感兴趣，然后将消息发布给所有已订阅的客户端。常见的代理有 Mosquitto、HiveMQ 和 EMQX。

发布者 (Publisher)

向代理发送数据（消息）并指定某个主题 (Topic) 的客户端。例如，一个向 home/livingroom/temp 发布数据的温度传感器。发布者不需要知道订阅者是谁。

订阅者 (Subscriber)

对特定主题注册了兴趣的客户端。当代理收到有关该主题的消息时，会将其转发给订阅者。一个客户端可以同时作为发布者和订阅者。

理解主题 (Topics)

MQTT 主题是用于过滤消息的层次结构字符串。它们使用正斜杠 / 作为分隔符，并且区分大小写。

主题结构

一个典型的主题如下所示：

myhome / groundfloor / kitchen / temp

这种层级结构允许对设备进行特定的寻址。

主题通配符 (Wildcards)

  • 单层通配符 (+)：
    home/+/temp 匹配 home/kitchen/temp，但不匹配 home/kitchen/fridge/temp。
  • 多层通配符 (#)：
    home/# 匹配以 home 开头的所有内容，例如 home/kitchen/temp 和 home/garage/light/status。这必须是主题中的最后一个字符。

服务质量 (QoS)

MQTT 提供了三种特定的服务质量级别用于消息传递。这允许设计者针对特定消息在网络开销和可靠性之间选择适当的平衡。

0

QoS 0

最多一次

也被称为“即发即弃” (Fire and forget)。消息只发送一次。不期望得到确认。如果连接断开或服务器繁忙，该消息将永久丢失。

使用场景：定期的温度传感器数据，丢失一百次读数中的一次并不关键。

1

QoS 1

至少一次

保证消息至少会被送达接收者一次。发送者将存储该消息，直到它收到 PUBACK 数据包。如果确认数据包丢失，可能会发生消息重复的情况。

使用场景：打开电灯开关。您肯定希望它被打开，执行两次指令是可以接受的。

2

QoS 2

只有一次

最安全但也是最慢的级别。通过使用四步握手协议，保证消息只被接收一次。这防止了重复消息的产生。

使用场景：银行交易、计费系统或重复数据会导致严重错误的关键警报。

实现示例

MQTT 几乎支持所有编程语言的客户端库（如 C, C++, Java, Python, Go, JavaScript 等）。

Python (Paho-MQTT)

Python 物联网应用程序的标准库。

import paho.mqtt.client as mqtt

# 连接时的回调函数
def on_connect(client, userdata, flags, rc):
    print(f"已连接，结果代码为 {rc}")
    # 在 on_connect 中订阅可以保证 
    # 如果断开连接后重连，我们也能重新订阅
    client.subscribe("home/sensors/#")

# 收到消息时的回调函数
def on_message(client, userdata, msg):
    print(f"{msg.topic}: {msg.payload.decode()}")

client = mqtt.Client()
client.on_connect = on_connect
client.on_message = on_message

client.connect("broker.hivemq.com", 1883, 60)
client.loop_forever()

JavaScript (Node.js)

使用 MQTT.js 库进行异步操作。

const mqtt = require('mqtt')
// 连接到一个公开的测试 Broker
const client  = mqtt.connect('mqtt://test.mosquitto.org')

client.on('connect', function () {
  console.log("已连接！")
  
  // 订阅 presence 主题
  client.subscribe('presence', function (err) {
    if (!err) {
      // 发布一条消息
      client.publish('presence', '你好 mqtt')
    }
  })
})

client.on('message', function (topic, message) {
  // message 是一个 Buffer 对象
  console.log(message.toString())
  client.end() // 关闭连接
})

常见问题解答

默认情况下，MQTT 以纯文本形式发送数据，这是不安全的。但是，生产环境的实现通常使用 TLS/SSL 来加密连接 (MQTTS)，通常在 8883 端口上运行。此外，还可以使用用户名/密码身份验证和客户端证书在代理 (Broker) 级别对设备进行授权。

保留消息是指“retained”标志被设置为 true 的普通 MQTT 消息。代理会存储该主题的最后一条保留消息。当新的客户端订阅该主题时，它会立即收到这条保留消息。这对于“状态”更新非常有用（例如，向刚刚唤醒的设备提供最后已知的温度）。

LWT 是一项功能，客户端通过它指定一条消息，如果客户端非正常断开连接（例如：电池没电，网络故障），代理会自动发布该消息。它允许其他客户端知道某个设备已经意外下线。

标准的 MQTT 使用 TCP 1883 端口。基于 SSL/TLS 的 MQTT 使用 8883 端口。基于 WebSockets 的 MQTT 通常使用 80 或 443 端口（如果加密），或者根据代理的配置使用如 9001 等自定义端口。

当客户端以“Clean Session = false”连接时，代理会创建一个持久会话。它会保存所有的订阅，并在客户端离线时为其排队 QoS 1 和 QoS 2 的消息。当客户端重新连接时，它将收到所有错过的数据。
