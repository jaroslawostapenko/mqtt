IoT pranešimų standartas

Įvaldykite MQTT protokolą. Lengvas, efektyvus ir patikimas pranešimų siuntimas daiktų internetui (IoT). Sukurtas nestabiliems tinklams ir mažo pralaidumo aplinkoms.

Paleisti simuliatorių

Kas yra MQTT?

MQTT („Message Queuing Telemetry Transport“) yra OASIS standartinis pranešimų protokolas daiktų internetui (IoT). Jis sukurtas kaip itin lengvas publikavimo / prenumeravimo (publish / subscribe) pranešimų transportas, idealiai tinkantis sujungti nutolusius įrenginius su nedidele kodo baze ir minimaliu tinklo pralaidumu.

Iš pradžių 1999 m. sukurtas IBM naftotiekių stebėjimui per palydovinius ryšius, dabar jis tapo de facto IoT standartu dėl savo efektyvumo ir patikimumo nestabiliuose tinkluose.

Kodėl jis toks populiarus?

  • ⚡ Lengvas: Mažiausias paketo dydis yra tik 2 baitai, tai sumažina tinklo apkrovą.
  • 🛡️ Patikimas: Siūlo 3 paslaugos kokybės (QoS) lygius pristatymui užtikrinti.
  • 🔄 Dvikryptis: Leidžia siųsti pranešimus iš įrenginio į debesį ir iš debesies į įrenginį.
  • 💾 Ilgalaikis (Persistent): Išsaugoti (retained) pranešimai leidžia naujiems įrenginiams iškart gauti paskutinę žinomą būseną.

Palyginimas: MQTT prieš HTTP

Nors HTTP yra žiniatinklio standartas, jis yra sunkus ir orientuotas į dokumentus. MQTT yra orientuotas į duomenis.

Architektūra ir komponentai

MQTT protokolas atskiria siuntėją (leidėją) ir gavėją (prenumeratorių) naudodamas centrinį komponentą, vadinamą Brokeriu.

Brokeris

Sistemos širdis. Jis gauna visus pranešimus, juos filtruoja, pagal prenumeratas nusprendžia, kas jais domisi, ir tada publikuoja pranešimą visiems prenumeruojantiems klientams. Populiariausi brokeriai yra Mosquitto, HiveMQ ir EMQX.

Leidėjas (Publisher)

Klientas, kuris siunčia duomenis (pranešimus) brokeriui tam tikra tema (topic). Pavyzdžiui, temperatūros jutiklis, publikuojantis duomenis į namai/svetaine/temp. Leidėjams nereikia žinoti, kas yra prenumeratoriai.

Prenumeratorius (Subscriber)

Klientas, registruojantis susidomėjimą konkrečia tema. Kai brokeris gauna pranešimą ta tema, jis persiunčia jį prenumeratoriui. Klientas gali būti ir leidėjas, ir prenumeratorius vienu metu.

Temos (Topics) supratimas

MQTT temos yra hierarchinės eilutės, naudojamos pranešimams filtruoti. Kaip skyriklį jos naudoja pasvirąjį brūkšnį /. Temos skiria didžiąsias ir mažąsias raides.

Temos struktūra

Tipinė tema atrodo taip:

manonamai / pirmasaukstas / virtuve / temp

Ši hierarchija leidžia specifiškai adresuoti įrenginius.

Temos pakaitos simboliai (Wildcards)

  • Vieno lygio (+):
    namai/+/temp atitinka namai/virtuve/temp, bet ne namai/virtuve/saldytuvas/temp.
  • Daugelio lygių (#):
    namai/# atitinka viską, kas prasideda „namai“, pvz., namai/virtuve/temp ir namai/garazas/sviesa/busena. Šis simbolis turi būti paskutinis temoje.

Paslaugos kokybė (QoS)

MQTT suteikia tris konkrečias paslaugos kokybės parinktis pranešimų pristatymui. Tai leidžia kūrėjams pasirinkti tinkamą balansą tarp sistemos apkrovos ir patikimumo konkretiems pranešimams.

0

QoS 0

Daugiausiai vieną kartą

Taip pat žinomas kaip „Iššauk ir pamiršk“ (Fire and forget). Pranešimas išsiunčiamas vieną kartą. Patvirtinimo nesitikima. Jei ryšys nutrūksta arba serveris užimtas, pranešimas prarandamas visiems laikams.

Naudojimo atvejis: Periodiniai temperatūros jutiklio duomenys, kai praleistas vienas rodmuo iš šimto nėra kritinis.

1

QoS 1

Bent vieną kartą

Garantuoja, kad pranešimas bus pristatytas gavėjui bent vieną kartą. Siuntėjas saugo pranešimą, kol gauna PUBACK paketą. Gali atsirasti dublikatų, jei patvirtinimas prarandamas.

Naudojimo atvejis: Šviesos jungiklio įjungimas. Jūs tikrai norite, kad ji įsijungtų, o jei signalas bus išsiųstas du kartus – tai priimtina.

2

QoS 2

Tiksliai vieną kartą

Saugiausias ir lėčiausias lygis. Garantuoja, kad pranešimas gautas lygiai vieną kartą, naudojant keturių žingsnių rankos paspaudimą (handshake). Tai apsaugo nuo dublikatų.

Naudojimo atvejis: Banko perlaidos, sąskaitų sistemos ar kritiniai pavojaus signalai, kur dublikatai gali sukelti klaidų.

Diegimo pavyzdžiai

MQTT turi kliento bibliotekas beveik kiekvienai programavimo kalbai (C, C++, Java, Python, Go, JavaScript ir kt.).

Python (Paho-MQTT)

Standartinė biblioteka Python IoT programėlėms.

import paho.mqtt.client as mqtt

# Atgalinis ryšys (callback), kai prisijungiama
def on_connect(client, userdata, flags, rc):
    print(f"Prisijungta su rezultato kodu {rc}")
    # Prenumeravimas funkcijoje on_connect užtikrina, 
    # kad prenumerata atsistatys praradus ryšį
    client.subscribe("namai/jutikliai/#")

# Atgalinis ryšys, kai gaunamas pranešimas
def on_message(client, userdata, msg):
    print(f"{msg.topic}: {msg.payload.decode()}")

client = mqtt.Client()
client.on_connect = on_connect
client.on_message = on_message

client.connect("broker.hivemq.com", 1883, 60)
client.loop_forever()

JavaScript (Node.js)

Naudojama MQTT.js biblioteka asinchroninėms operacijoms.

const mqtt = require('mqtt')
// Prisijungiama prie viešo testavimo brokerio
const client  = mqtt.connect('mqtt://test.mosquitto.org')

client.on('connect', function () {
  console.log("Prisijungta!")
  
  // Prenumeruojama buvimo (presence) tema
  client.subscribe('presence', function (err) {
    if (!err) {
      // Publikuojamas pranešimas
      client.publish('presence', 'Sveiki mqtt')
    }
  })
})

client.on('message', function (topic, message) {
  // message yra Buffer tipo
  console.log(message.toString())
  client.end() // Uždaromas ryšys
})

Dažniausiai užduodami klausimai (DUK)

Pagal nutylėjimą MQTT siunčia duomenis atviru tekstu, kas nėra saugu. Tačiau gamybinėse aplinkose paprastai naudojamas TLS/SSL ryšiui šifruoti (MQTTS), dažniausiai naudojant 8883 prievadą. Be to, įrenginių autentifikavimui brokerio lygmenyje gali būti naudojami vartotojo vardai/slaptažodžiai ir klientų sertifikatai.

Išsaugotas pranešimas yra įprastas MQTT pranešimas, kurio „retained“ vėliavėlė nustatyta į „true“. Brokeris saugo paskutinį išsaugotą pranešimą tai temai. Kai naujas klientas užsiprenumeruoja šią temą, jis nedelsdamas gauna šį pranešimą. Tai naudinga būsenos atnaujinimams (pvz., suteikiant paskutinę žinomą temperatūrą tik ką atsibudusiam įrenginiui).

LWT yra funkcija, kai klientas nurodo pranešimą, kurį brokeris automatiškai publikuos, jei kliento ryšys netikėtai nutrūktų (pvz., išsikrovus baterijai, įvykus tinklo gedimui). Tai leidžia kitiems klientams sužinoti, kad įrenginys netikėtai atsijungė.

Standartinis MQTT naudoja TCP prievadą 1883. MQTT su SSL/TLS naudoja prievadą 8883. MQTT per WebSockets paprastai naudoja prievadą 80 arba 443 (jei saugus), arba pasirinktinius prievadus, pvz., 9001, priklausomai nuo brokerio konfigūracijos.

Kai klientas prisijungia su „Clean Session = false“, brokeris sukuria ilgalaikę sesiją. Jis išsaugo visas prenumeratas ir QoS 1 bei 2 pranešimus išsaugo eilėje, kol klientas yra atsijungęs. Kai klientas vėl prisijungia, jis gauna visus praleistus pranešimus.
